# COMINO WORLD 批量内容发布操作方案

本文用于在用户逐条提供资料时，完成“一组资料 = 注册一个账号 + 创建一张物料卡 + 发布一条帖子”的重复性工作。

## 1. 每组资料需要包含

- 注册账号：至少 6 位，只能使用字母和数字，且不能重复
- 注册密码：至少 6 位
- 物料图片：至少 1 张本地图片路径
- 物料名称：必填，最多 15 字
- 开始时间、结束时间：必填，结束时间不得早于开始时间
- 地点：必填，最多 30 字
- 物料主 cn：选填，最多 15 字
- 物料份数：大于 0 的整数
- 活动标签：必须是系统内置标签之一
- 互换方式：`伸手` 或 `互换`
- 物料备注：选填，最多 50 字
- 帖子标题、正文
- 帖子状态：界面中的“交换中”对应接口值 `未换完`，“换完了”对应 `已换完`

资料缺少非关键选填项时可留空；必填项缺失时应先向用户询问，不能自行编造。

## 2. 推荐执行方式

优先使用正式后端 API，而不是直接修改 SQLite。API 会执行账号唯一性、字段长度、时间范围、图片类型、卡片归属和帖子快照等产品校验。只有 API 故障且用户明确允许时，才考虑事务化写数据库。

接口根地址：`https://comino.top/api`

### 步骤 A：检查并注册账号

1. `GET /auth/check-account?account=<账号>`，确认 `available: true`。
2. 在真正提交注册前，向用户展示账号并取得确认。
3. `POST /auth/register`：

```json
{"phone":"<账号>","password":"<密码>"}
```

4. 从响应中保存 JWT，仅保存在当前运行环境，不写入仓库、日志或操作文档。
5. 记录系统生成的默认昵称和头像，便于最终核验。

### 步骤 B：上传图片

对每张图片依次调用 `POST /upload`：

- 请求头：`Authorization: Bearer <JWT>`
- `multipart/form-data` 字段名：`file`
- 支持 JPEG、PNG、WebP、GIF；单张最大 10 MB

保存每次响应中的 `/uploads/...` URL，并保持用户给定的图片顺序；第一张是封面。

### 步骤 C：创建物料卡

调用 `POST /cards`，请求头包含 JWT，示例：

```json
{
  "name": "物料名称",
  "images": ["/uploads/example.jpg"],
  "startTime": "2026-09-01T10:00",
  "endTime": "2026-09-01T12:00",
  "location": "交换地点",
  "ownerCn": "物料主cn",
  "quantity": 1,
  "eventTag": "其他",
  "exchangeMethod": "互换",
  "notes": ""
}
```

保存响应中的卡片 ID。随后调用 `GET /cards`，确认该卡片属于新账号，图片数量、时间段和其他字段均正确。

### 步骤 D：发布帖子

资料完整后自动准备发布，不再重复询问密码、账号或字段内容。发布属于公开的对外操作，出于安全要求，调用发布接口前仍须用一句话展示最终标题/正文摘要、状态和关联物料卡，并取得当次即时确认；不能用“以后都不用确认”替代这一步。

确认后调用 `POST /posts`：

```json
{
  "title": "帖子标题",
  "content": "帖子正文",
  "status": "未换完",
  "images": [],
  "materialCardIds": ["<卡片ID>"]
}
```

帖子不允许直接上传图片，因此 `images` 固定为空数组。每条帖子最多关联 3 张属于当前账号的物料卡。

## 3. 发布后的强制核验

调用 `GET /posts/<帖子ID>`，逐项检查：

- `user_id`、作者昵称和头像属于新注册账号
- 标题、正文、状态正确
- `images` 为空
- `materialCards` 数量与选择一致
- 每张卡的 `sourceCardId`、图片、名称、时间段、地点、份数、标签和互换方式正确

再读取社区第一页 `GET /posts?page=1&limit=20`，确认新帖进入信息流。若未出现，先检查联合筛选条件和发布时间排序，不要重复发布。

## 4. 常见失败及处理

- 账号重复：更换账号并重新向用户确认，不要尝试接管已有账号。
- 上传失败：检查文件是否存在、格式和大小；不要只写图片 URL 绕过上传。
- 时间错误：使用本地无时区格式 `YYYY-MM-DDTHH:mm`，结束时间必须不早于开始时间。
- 卡片保存成功、帖子发布失败：保留卡片 ID，修正帖子参数后重试；先查询个人帖子，防止网络超时导致重复发布。
- 接口返回 401：重新登录获取 JWT，不要修改数据库中的密码。
- 请求超时：先用查询接口判断操作是否实际成功，再决定是否重试。
- UI 原生日期控件无法被自动化可靠驱动：可改用正式 API；这属于自动化工具限制，不代表产品日期选择器失效。

## 5. 安全与清理

- 不在仓库、终端脚本或最终回复中长期保存密码、JWT、SSH 私钥。
- 不把用户密码、联系方式或其他私密信息写进公开帖子。
- 流程测试产生的账号、帖子、物料卡和上传图片应明确标记为测试数据。
- 删除公开测试帖、账号或服务器文件属于破坏性操作，执行前再次确认。
- 清理顺序建议为：帖子及其关系/快照 → 物料卡及图片关系 → 用户相关记录 → 用户 → 已确认无引用的上传文件。
- 数据库清理必须使用事务，并在执行前创建带时间戳的数据库备份；图片仅在确认没有任何表引用时删除。
